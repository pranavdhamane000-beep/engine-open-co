1. Document Authority and Use
1.1 Purpose
This Development Execution Specification (DES) converts the v3.2 implementation-level development plan into actionable engineering work. It defines the systems to implement, their prerequisites, exact source-file ownership, dependencies, chronological work, internal behavior, algorithms, data structures, public interfaces, integration points, failure behavior, and validation requirements.
The specification covers the foundation required before full character, combat, cinematic, and advanced effects development. Its primary output is a Windows editor and headless exporter whose project mutations, evaluated scenes, simulation, audio, and rendering share deterministic contracts.
1.2 Normative language
The words MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are normative. A work package is complete only when its implementation, tests, diagnostics, and integration gates are complete. A compiling subsystem without its required validation is incomplete.
All paths are relative to animation_engine/ unless explicitly stated otherwise. Rust signatures are normative at the responsibility and data-contract level; names may receive Rust-mandated lifetime annotations, but semantics, ordering, units, and failure behavior MUST NOT change without an ADR and schema review.
1.3 Implementation status and change control
This is a greenfield implementation baseline. No repository implementation is assumed to exist. Before changing a normative contract, the developer MUST:
Create or update an ADR under docs/adr/.
Identify affected schemas, golden files, migrations, and downstream crates.
Increment the relevant schema or algorithm version when persisted bytes or output semantics change.
Add compatibility and migration tests before removing old behavior.
Update the requirement traceability matrix in Section 22.
1.4 Required engineering outcomes
The completed foundation MUST provide:
A versioned project with stable identities and content-hashed assets.
Exact rational timeline positions, including subframes and NTSC rates.
Atomic, revision-checked command transactions and undo/redo.
Crash-safe project saves and output publication.
Immutable scene snapshots and canonically ordered events.
Fixed-step simulation with reproducible random streams and seeking.
A linear-HDR forward render graph with explicit alpha and motion-vector behavior.
DXGI-informed GPU resource budgeting without unsupported no-spill claims.
Deterministic offline 48 kHz audio and independent real-time preview.
Bounded, fixed-quality, headless FFmpeg export.
An egui editor that reads snapshots and issues commands but never mutates scene storage directly.
Repeatable unit, property, golden, integration, fault-injection, benchmark, and long-export validation.

2.2 Determinism boundary
The deterministic contract applies to the same engine build, project revision, ordered asset-manifest hashes, render/export settings, random algorithm version, target architecture, and declared backend environment.
The following MUST be byte-identical under that contract:
Canonical serialized project data.
Scene snapshots and event logs after canonical encoding.
CPU simulation checkpoints and per-tick state hashes.
Offline PCM audio before any lossy audio codec.
Export job manifests and frame/sample counts.
GPU pixels MUST be bit-identical only on the explicitly tested device, backend, driver, and build. Cross-device golden images use documented tolerances. Lossy video and audio are validated by decoded metadata, counts, timing, and approved quality criteria rather than PCM or frame-byte identity after encoding.
2.3 Performance boundary
Preview quality may adapt to measured frame time. Export quality MUST NOT adapt. No frame-rate or export-time claim is valid without the benchmark scene, exact settings, engine commit, FFmpeg build, adapter, and driver version. Memory-pressure handling may evict caches during export but MUST NOT reduce requested output quality or silently substitute assets.

7. Cross-System Data and Lifecycle Rules
7.1 Canonical serialization
Persisted collections with semantic ordering use arrays or ordered maps. Where canonical bytes are hashed, object keys and collection entries are sorted by their specified stable keys. Floating-point values must be finite; canonical state hashing encodes their bit patterns explicitly. Wall-clock timestamps may appear in informational reports but never in deterministic project, simulation, or render hashes.
7.2 Revision invalidation
A successful command transaction increments ProjectDocument.revision exactly once. Snapshot caches key on (scene_id, revision, FramePos). Simulation input caches additionally key on the simulation algorithm version and configuration. Render history becomes invalid when scene revision, camera cut state, target generation, or discontinuous seeking requires it. Cache eviction never increments revision or changes results.
7.3 Cancellation and cleanup
Long-running import, seeking, export, and device recovery operations accept a cancellation token. Cancellation stops new work, closes process inputs, terminates and reaps child processes when necessary, unmaps readback buffers, and leaves no final destination partially written. Temporary artifacts are removed unless explicit diagnostic preservation was requested.
7.4 Diagnostics
Every library exposes typed errors with stable categories. Binaries add context and map errors to exit codes. Diagnostics MUST include relevant safe context: asset ID/path, command ID, expected/actual revision, scene/entity ID, frame, simulation tick, GPU resource ID, export stage, or FFmpeg exit status. Secrets and arbitrary user file contents are not logged.

9.6 Internal logic
Each probe is isolated and returns a nonzero status on unmet requirements. GPU selection defaults to an explicitly configured adapter or a validated selection rule; it never assumes the first adapter is the RTX. Probe output contains the adapter, driver, formats, limits and errors needed to reproduce decisions. FFmpeg stderr is drained on a bounded reader thread. Temporary files are created beside their destination so replacement remains on one volume.
9.7 Algorithms
GPU/readback probe. Input: optional adapter ordinal and known compute inputs. Output: GpuProbeReport. Enumerate adapters, request required limits, compile WGSL, dispatch one workgroup, submit, map the output buffer, compare exact integers, unmap and release. Unsupported compute, shader compilation, device loss and mapping failure are distinct failures.
Adapter correlation. Input: Vulkan VkPhysicalDeviceIDProperties.deviceLUID when valid and DXGI AdapterLuid. Output: matched AdapterIdentity or IdentityUnavailable. Compare all 64 LUID bits and cross-check vendor/device IDs. Never substitute the primary desktop adapter on mismatch.
Media probe. Input: explicit FFprobe/FFmpeg paths and media path. Output: stream metadata and decoded PCM count. Select a stream by index, decode a bounded duration, resample to 48 kHz and verify the expected count within declared decoder delay behavior. Malformed JSON, missing streams, timeout and nonzero exit fail.
Replacement probe. Input: NTFS test directory and fault point. Output: old or new complete state. Write and flush a temporary file, invoke replacement, reopen both destination and backup, and verify hashes. A fault before commit must leave old bytes; a fault after commit may leave new bytes but never mixed bytes.

10.6 Internal logic
A rational always has a positive denominator, is reduced by its greatest common divisor, and represents zero as 0/1. FramePos contains a whole frame and a subframe normalized to [0,1). Normalization carries overflow into the frame. Frame n starts at exact time n/fps; an arbitrary position is (frame + subframe)/fps.
The canonical timeline supports negative positions for stateless evaluation. Export ranges and stateful simulation may impose nonnegative restrictions at their own boundaries. UI formatting and floating-point interpolation never feed rounded values back into persisted time.
10.7 Algorithms
Frame containing a time. Input: rational seconds t and positive rate fps. Compute whole=floor(t*fps) and fraction=t*fps-whole; checked-convert whole to i64; return {whole,fraction}. At a negative exact boundary, floor selects the mathematically preceding frame rather than truncating toward zero.
Frame-start audio interval. For whole frame f, frame rate fps_num/fps_den, and sample rate sr:
start = floor(f     * sr * fps_den / fps_num)end   = floor((f+1) * sr * fps_den / fps_num)interval = [start, end)
Adjacent intervals share an endpoint but no sample. For arbitrary FramePos, compute its exact rational time and apply floor(time*sr). Use ceil only for a covering decoder range that must include every source sample touched by interpolation.
Rational arithmetic. Inputs are normalized operands. Compute with BigInt, reduce, then checked-convert numerator and denominator to i128. Division by zero, nonpositive frame rate, nonfinite external input and overflow return errors. No arithmetic wraps.

12.6 Internal logic
The CommandProcessor is the single writer. An envelope is accepted only when its project ID, schema and expected revision match. Empty batches are rejected. Commands execute on a cloned document; each validates current transactional state and returns an inverse. Any error drops the clone and all inverses. Success swaps the clone, increments revision once, records the transaction and publishes notifications after commit.
Undo applies the selected transaction's inverses in reverse order to a clone and commits a new revision. Redo reapplies forward commands. A new forward edit clears redo. History is session-local and not persisted as authoritative project state.
Dry-run checks schema, references and invariants, but apply repeats all checks under the writer boundary. This prevents a validate-then-apply race.

Atomic save. Validate and serialize before touching disk. Create .project.anim.json.&lt;uuid&gt;.tmp beside the destination with create_new; write all bytes, flush and sync_all. 14.6 Internal logic
SimTick(0) is the initialized state before any simulation step. For ticks_per_frame=N, whole frame f begins at tick f*N; step_once advances exactly one tick. The step duration is computed once from exact configuration as 1/(fps*N) and converted to the declared floating-point working type; mutable seconds are never accumulated.
At each tick, the engine applies scheduled events, samples required snapshot data, emits particles, accumulates spring forces, integrates, runs a fixed number of solver iterations, updates lifetimes and removes expired entries by stable filtering. Collections affecting results are sorted vectors or BTreeMap. Rendering, hashing and checkpointing do not mutate simulation state or consume random values.
Live preview may skip presentation frames but MUST NOT skip simulation ticks when deterministic state is expected. If the preview cannot catch up within its configured budget, it pauses and reconstructs or displays a diagnostic rather than silently taking a different step size.
14.7 Algorithms
Clock and event scheduling. SimTick is signed for timeline arithmetic, but stateful replay supports ticks at or above zero. Convert frame f to tick with checked f*N. For event time t, compute scheduled_tick=ceil(t*simulation_rate). Events at an exact tick boundary schedule to that tick. Within one tick, preserve canonical scene-event order. For a spawn scheduled at tick k, compute exact age=time_of_tick(k)-t; convert once to working precision and use the same force function to initialize its state. Negative age is an internal error.
Philox random access. Input: StreamKey, absolute tick, semantic draw_index, and lane 0..3. Derive a 128-bit key from BLAKE3 over domain "anim_engine/philox/v1", project seed, system ID, emitter/entity ID, stream purpose and stream version. Split into two little-endian u64 Philox keys. Counter words are (tick_low,tick_high,draw_index,0). Execute ten Philox4x32 rounds and select the lane. Convert to f32 using the upper 24 bits divided by 2^24, yielding [0,1). Draw indices come from fixed semantic channel tables and deterministic spawn/particle ordinals, never a “next random” cursor. Lane above three, negative tick or overflow returns an error.
Seek. Input: canonical initial state, immutable project/snapshot source, checkpoint cache and target tick. Select the greatest verified checkpoint not exceeding target; otherwise restore tick zero. Replay event schedules and fixed steps until target. Never restore a later checkpoint or reuse future mutable state. Return a state whose canonical hash equals sequential execution at target.
Warm-up and export. Restore the nearest valid checkpoint before export_start_tick; advance in warm-up mode to that tick; then enter export mode. Warm-up performs all internal spawns, random draws, events and solver work but suppresses external one-shot presentation effects such as device audio. Changing checkpoint cadence or warm-up chunk size cannot change the exported state. Exhaustion of a replay budget triggers continued replay with a higher explicit limit or a clear error, never approximate state.
Checkpoint hashing. Canonically encode tick, algorithm versions, configuration, particles/springs in stable ID order, generation counters and event cursor. Encode floating-point bit patterns little-endian after finite validation. Hash with domain separation. Malformed or mismatched checkpoints are discarded and reconstructed from an earlier verified state.

15.7 Algorithms
Draw extraction and transparent sort. Input: immutable scene/simulation data, camera and material definitions. Alpha conversion. Authoring straight-alpha color is decoded to linear and premultiplied as rgb_premul=rgb_linear*alpha. Assets already marked premultiplied are not multiplied again. Velocity. Compute unjittered current and previous clip positions using current/previous camera and instance transforms. Convert NDC to UV using uv=ndc_xy*vec2(0.5,-0.5)+0.5. Store current_uv-previous_uv. If previous w&lt;=0, a particle is newly spawned, or history is invalid, set validity to zero. Scene load, discontinuous seek, teleport, camera cut, projection change, topology discontinuity and target resize invalidate history. Previous transforms update only after successful submission.
Post graph. Input: declared effect settings and clean targets. Execute enabled passes in versioned order: depth-aware effects, motion blur, bloom and other linear HDR effects; tone map; display-referred grade; output transfer. A disabled pass declares no reads/writes and returns its input target. Ping-pong targets alias only when graph lifetimes do not overlap. The final alpha mode converts premultiplied output to straight only when the selected codec requires it, with zero-alpha RGB explicitly defined.

16.6 Internal logic
Query only the adapter correlated with the rendering device. If identity cannot be established confidently, continue with internal estimates, use a conservative target and mark telemetry unavailable; never query an unrelated adapter. DXGI values change asynchronously, so every allocation still requires actual error handling.
The initial target fraction is 0.80 of the current budget, reduced further by a configured safety reserve. These are configuration defaults, not hardware promises. Eviction starts after the configured consecutive over-budget samples and continues below a lower release watermark. Actual allocation failure bypasses sampling delays. The manager never frees live, mapped, locked, GPU-only-without-restore, or in-flight resources.
16.7 Algorithms
Budget snapshot. Input: DXGI local-segment values and internal accounted bytes. Output: immutable BudgetSnapshot. Compute effective_usage=max(observed_usage,accounted_usage) for conservative policy. soft_target=min(budget*target_fraction,budget-safety_reserve) using saturating arithmetic. Differences between observed and accounted bytes are diagnostics, not proof of ownership by another process.
Eviction plan. Input: snapshot, registry, completed serial, required current-frame set and release target. Exclude locked, mapped, required, unrestorable GPU-only and resources whose last_used_serial&gt;completed_serial. Prefer disk-backed/regenerable, then CPU-shadowed resources. Order by ascending priority, oldest last-used serial, lowest reload cost and stable resource ID. Stop after predicted release satisfies the lower watermark. If insufficient candidates exist, defer optional uploads and reduce preview-only optional targets; export reports OOM if pinned requirements cannot fit.
Allocation preflight. Obtain a fresh snapshot within policy, estimate bytes and add a reservation. If projected usage exceeds the hard trigger, plan eviction and poll only known GPU completions with a bounded wait. Attempt wgpu creation. On success commit the reservation and register the resource. On failure roll back the reservation, perform one bounded additional eviction/degradation policy, and retry only if the policy allows. Required export resources are never silently dropped.
Fence lifecycle. Assign a serial at every queue submission. Record the highest serial referencing each resource. on_submitted_work_done advances completed serial in callback order through an owned tracker. Evict only when last_used_serial&lt;=completed_serial. Device loss invalidates serial assumptions and all residency records; rebuild from CPU/disk sources.

17.6 Internal logic

It does not allocate, block on disk/GPU work, or acquire the project lock. Pause, seek, rate change, underrun and device restart publish clock-generation changes so video does not infer continuity across a discontinuity.
17.7 Algorithms
Frame-range conversion. Input: [first_frame,end_frame) and FrameRate. Output: [first_sample,end_sample) at 48,000 Hz. Use WP01 frame_samples at both boundaries and checked-convert to nonnegative export offsets. N=end_sample-first_sample is the expected pre-mux PCM sample count. Reject zero rates, reversed/empty ranges, negative export samples and overflow.
Plan construction. Select every clip intersecting the output range. Clip the timeline range exactly, preserving the corresponding source offset. Sort by start sample then stable clip ID. Validate nonzero source length for loops, finite gains, valid fades, supported channel/rate metadata and matching content hashes. Missing sources fail before rendering.
Source mapping and resampling. Decode source PCM using the pinned decoder. Resample with one locked rubato configuration into canonical 48 kHz access, keyed by (content_hash,decoder_version,resampler_version,settings_hash). Streaming resampler state is private to an asset decode session and independent of output mix chunk size. Source position for an output sample is source_start+(output_sample-clip_timeline_start); looping uses checked modulo by canonical source length. Exhausted nonlooping sources contribute silence.
Mix. For each output sample, process intersecting planned clips in canonical order. Convert mono to stereo using the declared gain; preserve stereo; reject unsupported channel layouts until explicitly added. Apply source gain and sample-indexed fade gains. Accumulate in f64 in stable order, clamp to [-1,1], and round once to signed 16-bit using a specified symmetric rule. Do not apply adaptive normalization. Optional loudness processing is a later explicit two-pass stage with its own settings and tests.
Preview clock. A clock snapshot contains generation, anchor timeline sample, device samples and rate. While playing, position derives from the current callback counter within one generation. Pause freezes; seek replaces anchor and increments generation; underrun marks discontinuity; callback data after stream destruction is ignored by ownership.

18.7 Algorithms
Export execution. Input: saved project path, immutable settings, destination and overwrite policy. Output: ExportReport or typed failure with previous destination untouched. Let N=end-first. For k=0..N-1, evaluate first+k, ensure simulation has reached its frame boundary, render, acquire a free slot, copy to the padded buffer, map/read/unmap, pack exactly width*height*4 bytes, write to FFmpeg and release the slot. Zero frames, excessive dimensions, stride overflow and missing frames fail before publication.
Readback state machine. Slots begin Free; transition to Submitted after copy/submission, Mapped after successful asynchronous mapping, Ready after bytes are copied/unmapped, and Free after encoder consumption. Any error returns a slot to a safe state only after unmapping. Device loss invalidates all slots and aborts the job. No slot may be reused while a map or GPU write is outstanding.
FFmpeg encoding. Construct a versioned argument array. Raw input specifies rawvideo, rgba, exact width/height and fps_num/fps_den; input comes from pipe:0. Output selects the resolved profile and explicit BT.709 or other declared conversion metadata. Never use shell string interpolation. Stderr is drained into a bounded tail buffer while complete diagnostics may stream to a job log.
Mux and verification. Map video and audio explicitly, copy video, select the declared audio codec and do not use -shortest. Decode final video and count complete frames and trailing bytes; require exactly N and no trailing bytes. Require pre-mux WAV samples to equal WP01 expected count. PCM final audio must match exactly. Lossy AAC is checked against declared priming/edit-list behavior and expected timeline duration; unexplained added/missing samples fail. Verify codec, pixel format, dimensions, stream order and rational frame rate.
Publication. Keep all temporary files on the destination volume. For a single file, use shared atomic replacement with explicit overwrite policy; never delete then rename. For PNG output, build a complete sibling directory and rename it only after verification, with an explicit directory replacement policy. Verification or publication failure leaves any previous destination untouched.

19.6 Internal logic
The UI reads Arc&lt;EditorSnapshot&gt; values and issues commands containing stable IDs. It never retains mutable scene references. A stroke freezes the view transform at pointer-down, captures coalesced points oldest to newest and displays an uncommitted overlay. Only valid primary pen contact completion creates CommitStroke. After commit, the stroke renders from subsequent project snapshots rather than the transient overlay, preventing double rendering.
GetPointerPenInfo supplies pressure, tilt, rotation and button/eraser metadata; GetPointerFramePenInfoHistory supplies coalesced history. Pressure normalizes from the device range to [0,1]. Pointer capture and focus are owned by the active stroke. Cancellation discards transient state without a project mutation.
Preview quality uses measured frame-time EMA and hysteresis. Its state is session-local and never serialized into project or export settings.
19.7 Algorithms
Stroke state machine. Idle -&gt; Capturing -&gt; CommitPending -&gt; Committed -&gt; Idle; any capturing/pending state may become Cancelled under allowed conditions. On pointer-down validate tool, primary contact and pointer ID; create stable stroke/command IDs and freeze view transform. On update append validated coalesced points and render overlay. On up append the final point, issue one command and retain the same command ID for retry after a transient submission failure. Duplicate up, pointer/mouse synthesis and redraw do not commit again. Cancellation releases capture and drops overlay state.
Coordinate and point validation. Convert client to scene coordinates with the frozen inverse view transform. Reject nonfinite coordinates. Clamp pressure to [0,1]. Preserve hover pressure as metadata but begin drawing only on contact. Enforce a configured maximum point count; when exceeded, cancel with a visible diagnostic or use a versioned deterministic simplifier, never an unbounded allocation. Eraser input selects an explicit eraser command rather than a drawing stroke.
Adaptive quality. Start at scale 1.0 and full preview effects. Downgrade one level after eight consecutive frames above target; upgrade one level only after 120 frames below 70% of target. Allowed scales are 1.0, 0.75, and 0.5. Reset samples after breakpoint, seek, suspension, resize or device recovery. Never change project data, canonical simulation stepping or export profiles.

Algorithms
Forward kinematics. Iterate parent-before-child topological order:
world[bone] = world[parent] * rest_adjustment * local[bone]
Use the declared transform convention and finite-value validation.
Two-bone analytic IK. Given start S, target T and lengths L1,L2, calculate reachable distance d and clamp to [|L1-L2|+epsilon,L1+L2-epsilon]. Interior angles use safe inverse cosine. Select the bend side from a pole vector or authored sign. Unreachable and fully extended cases return diagnostics and clamped output, never NaN.
FABRIK. Alternate forward end-effector and backward root passes for a fixed maximum number of iterations. Test convergence before an extra pass. After each affected joint update, project limits.
CCD. Process joints from effector to root. Compute the cross-product axis between bone-to-target and bone-to-effector and rotate proportionally to reduce error. Clamp gain and iteration count and project limits after each joint.
Jacobian DLS. Build a planar position and orientation Jacobian for the active chain. Solve:
delta = J^T * (J * J^T + lambda^2 I)^-1 * error
Use explicit 2×2/3×3 arithmetic. Detect rank loss with determinant epsilon, increase damping, and limit delta magnitude. Apply, project limits and record convergence or singular diagnostics.
IK/FK blending. Solve IK, convert its resulting local rotations into FK control values, then blend source FK and converted IK pose by alpha. This avoids a visible jump when switching.
Contact locking. Store a world-space pin and release rule. The stabilization pass computes pelvis correction so a locked foot does not slide while root motion continues. Release conditions are authored explicitly rather than inferred from frame rate.

Algorithms
Substep schedule. Given rational step dt and maximum stiffness frequency f0, calculate angular frequency omega=2πf0, choose a fixed stability multiplier, derive n_substeps=clamp(ceil(dt/h_max),1,16), and use h=dt/n_substeps. Chain islands share one schedule so iteration count is stable.
Distance constraint. For nodes i-1,i, compute delta and distance. Use the stored rest direction if nodes coincide. Correct both endpoints according to inverse mass, clamp stretch and preserve a pinned anchor.
Bend constraint. Use parallel transport frames for each chain segment. If angle exceeds bend_limit, rotate the tip around the shared axis by the excess, damped by configured stiffness/damping.
Collision. Evaluate analytic signed-distance shapes—sphere, capsule, plane and ellipsoid. Push nodes outside by surface radius, split normal/tangential velocity, apply restitution and friction. Start-inside nodes receive bounded push-out iterations; unresolved cases mark the chain Stuck, stop integration and report rather than explode.
Secondary follow. Drive a target offset from character velocity. Solve a second-order lag with fixed critical damping. Anchor teleport resnaps without applying an impulse.
Warm-up. Before first visible frame, integrate the chain over its authored warm-up window using anchor pose history. Suppress external contact/audio events. Commit only settled final state. If project duration is shorter, clamp and report.
Particle count. For rational rate r and step h, expected=r*h. Accumulate fractional carrier. Use deterministic whole plus Bernoulli Philox draw. A burst emits exactly its count.
Particle spawn. Each attribute uses a distinct stream label: position, direction, life, size, color, subframe. Spawn subframe position is integrated from the exact event time, not all particles forced to frame end.
Particle motion. Apply gravity, wind, curl noise, drag and collision in fixed order. Use stable particle index and deterministic removal compaction.
Stylized smear. Use driver velocity magnitude for stretch, clamped to max aspect. Blend orientation toward current velocity with fixed easing.
Sword trail. Maintain a ring buffer of weapon tip positions keyed to tick. Build ribbon width from quantized speed and merge points below the degenerate epsilon.
Impact flash. Layer core, halo, sparks and rim envelopes, each with analytic time response. Its peak may reference the same contact FramePos as audio, but audio scheduling remains independent.
Speed lines. Generate camera-facing radial quads around subject screen bounds. Use Philox jitter and camera roll/FOV from the current evaluated camera state.
Post chain. Resolve requests by fixed (order, id) order, cap enabled effects at the documented maximum and render into ping-pong linear HDR targets before tone map. Tone map and output transfer remain WP06-owned.

Internal logic
Camera evaluation is part of deterministic scene simulation and occurs at CameraStage::ORDER = 320, after pose evaluation and before secondary motion/VFX stages. For each live camera:
Resolve the active shot from ShotBoard::active_at(FramePos).
Sample the authored camera track at exact rational FramePos.
Apply motion layers by (priority, MotionLayerId).
Apply framing constraints, if enabled.
Apply follow aim using subject world bounds and analytic or canonical sampled velocity.
Add shake/handheld offsets after framing so stabilization noise does not fight the solver.
Resolve focus distance.
Evaluate screen-position and 180-degree continuity rules.
Advance camera history using a cut/seek/resize/projection policy.
Emit immutable camera pose, matrices, focus, shutter, transition mix and epoch data.
Inactive cameras do not run unless a shot explicitly keeps them active. A blend evaluates both cameras; transitions never fake the second shot.
Algorithms
Rational track sampling. Sort keys by FramePos. Before the first key use the pre-extrapolation mode; after the last use post-extrapolation. For interpolation, calculate u=(t-t0)/(t1-t0) exactly, apply the versioned easing function, then convert to float only for the geometric result. Rotations use shortest-arc spherical interpolation; near-parallel tangents use a documented linear fallback.
Camera projection. Perspective FOV is validated in (1°,140°). Orthographic size must be positive. near &lt; far is required. Aspect comes from output configuration and is not inferred from editor window size during export.
Motion layer composition. Motion layers are applied in a fixed priority order. Pan/tilt/roll rotate local axes; truck/pedestal/dolly translate camera-local axes; zoom changes FOV without translation; dolly zoom explicitly combines FOV and translation layers. A layer is a delta proposal, not a mutable second timeline.
Rail movement. Build a centripetal Catmull-Rom spline. Merge zero-length segments. Precompute 256 arc-length samples as canonical cumulative values and interpolate distance through binary search plus a bounded refinement. This makes motion speed stable under frame-rate changes.
Framing solver. Given subject bounds, target screen center and target screen size, calculate required camera distance and lateral offsets. Solve dolly/truck/pedestal first, then angular pan/tilt only if allowed. Clamp to authored min/max bounds. If no feasible pose exists, report residual and return the nearest valid pose; never silently violate a hard constraint.
Follow. Predict subject position as position + velocity * lead. Smooth aim with a critically damped second-order response using canonical time. If look direction nearly parallels up, reuse the previous up reference and emit UpDegenerate.
Shake/handheld. Use Philox streams keyed by (scene_seed, camera_id, stream_label, tick, draw_index). Sum a fixed octave table and quantize sampling to simulation ticks. Handheld adds a low-pass drift and breathing oscillator. Same seed/tick must produce the same value.
Focus. FocusSource may be explicit distance, tracked subject, or last valid probe. Rack focus interpolates exact rational distance over a keyframe window. Orthographic mode emits CoC=0 and a warning rather than calculating meaningless DOF.
Continuity. Define the axis of action from two subject anchors or authored points. Classify camera side relative to this axis. Crossing generates one event per crossing. Report or apply an authored automatic fix only through a subsequent command; do not mutate other shots implicitly.
Transitions. Hard cut changes active camera and bumps history epoch. Crossfade blends two live cameras. Wipe uses screen mask shapes. Match cut enforces outgoing/incoming framing similarity; failure becomes a hard cut plus warning. Transition mix uses monotonic rational time.
Motion vectors. Reconstruct current and previous UV with current and previous view-projection matrices. If epoch differs from previous frame, set previous matrix equal to current, producing zero camera motion vector. Object velocity remains valid. Clear temporal history on cut, projection change, resize, discontinuous seek or teleport.

Internal logic
Planning executes as a fixed-order pipeline over an immutable snapshot and event sequence.
The planner receives FramePos, SceneSnapshot, SimState and sorted SceneEvent data.
Boundary detection scans events from last_processed_frame forward and produces sorted segment boundaries.
Subject selection chooses primary and secondary actors for each segment.
Framing constructs a world-space bounding target from selected actor bounds.
The camera solver proposes a pose and lens setting that contains the target.
Cut, eyeline, screen-direction, distance-transition and beat rules propose patches.
Conflict resolution chooses a surviving command for each protected camera channel using the fixed priority order.
The override store suppresses auto-generation where a user has protected a channel and frame range.
The result becomes one command batch.
Dry-run returns the batch; apply routes it through the standard command processor and creates exactly one undo transaction.
Re-planning regenerates only invalid segments unless replan_all is requested.
The planner never mutates simulation state. It never reads wall-clock time, GPU frame rate, editor selection or mouse latency. Rule patches are immutable proposals and cannot depend on hash-map iteration order.
Algorithms
Segment boundary detection. Input: sorted events, last end, minimum cut gap. Output: unique boundaries. For each event, ignore occurrences closer than the minimum gap to the preceding accepted boundary. Start a new segment when the combat pair changes, primary actor velocity crosses the configured threshold and remains crossed for the configured dwell window, a beat event fires, or an authored cut marker occurs. Preserve event order and deduplicate identical times.
Subject priority scoring. Score each actor using (explicit_subject, combat_active, contact, beat, velocity, screen_prominence) with numeric priority first and NodeID byte order as the final tie break. Select primary and secondary handles. No floating-point comparison may determine priority unless explicitly quantized.
Framing target. Union selected actor world-space rectangles. Apply a distance multiplier: extreme long, long, medium, close and extreme close use pinned multipliers. Add configurable safe-area margin. Return center, half-width and half-height.
Perspective camera solve. Given target half-width w, half-height h, screen aspect a and vertical FOV fov, calculate:
required_half = max(w, h / a)z = required_half / tan(fov / 2)z = clamp(z, min_z, max_z)
If clamping prevents full containment, emit a diagnostic rather than silently changing lens. Orthographic solve sets half-size to the required value.
Eyeline yaw. For a dialogue pair, compute world-space line from primary to secondary. Convert to camera yaw and compare with proposed yaw. If outside the quantized tolerance, apply a yaw correction. Use mathematical floor/quantization before comparison to prevent floating-point tie instability.
Screen-direction preservation. Maintain a dominant axis per actor pair across segments. If a proposed cut crosses the axis, require either an explicit neutral cut, a reverse-angle rule, or a user override. A violation is a conflict rather than an implicit camera change.
Conflict resolution. Group proposed patches by protected channel and overlapping frame range. Resolve by fixed priority: user override, hard eyeline, screen direction, beat emphasis, distance transition, default. Sort competing rules by priority, rule ID and stable segment ID. Emit one surviving command and log suppressed rules.
Re-planning. When new events arrive after a saved plan, create a ReplanToken at the first affected boundary. Restore affected segment state from canonical events and regenerate only those segments. If manual override data exists in a segment, preserve protected channels and rerun conflict resolution.

Internal logic
For each simulation tick:
Restore deterministic state from the nearest checkpoint or project start when seeking.
Read base pose and selected subjects from the current shot segment and immutable snapshot.
Evaluate time scaling and speed ramp using canonical tick time; clamp to a nonzero minimum.
Evaluate continuous movement layers in a fixed order: orbital, arc, whip, dolly zoom, crane, handheld, trauma, collision correction, occlusion correction, adaptive framing, lead/follow, continuity, lens.
Compose the final pose through a versioned blend rule rather than arbitrary mutable accumulation.
Compute angular and linear velocity from current and previous deterministic state.
Calculate post-processing shutter and DOF parameters from final pose, subject focus and event context.
Emit or stage command patches.
Advance layer state and hash it for checkpoint equality.
Live preview may run the controller at simulation rate. Export calls the same controller and cannot select a different motion integrator. Adaptive preview quality cannot alter camera pose.
Algorithms
Trauma accumulation and decay. For contact intensity I at origin p:
distance = clamp(||p - camera_position||, 0, decay_radius)weight = 1 - distance / decay_radiustrauma = clamp(trauma + I * weight, 0, 1)trauma_next = max(0, trauma - decay_per_tick)
Shake offset uses trauma² times quantized Philox noise from the camera/layer stream. Offset channels are ordered by layer ID. Spatial decay does not alter canonical contact event ordering.
Orbital tracking. Given center c, radius R and angular velocity ω:
angle(k) = angle_0 + ω * time_of_tick(k)position = c + R * [cos(angle), sin(angle)]orientation = look_at(c)
Angle is normalized modulo 2π using exact quantized values. Center loss freezes the last valid center and fades movement weight to zero over a configured duration.
Dolly zoom. To maintain projected subject half-height h, distance and vertical FOV obey:
fov(z) = 2 * atan(tan(fov_0 / 2) * z_0 / z)
Clamp z, fov and change rate before calculation. Near-zero distance and negative distance are validation errors.
Whip pan. Use a versioned eased yaw trajectory, settle overshoot, and derive shutter-angle increase from final angular velocity. A whip is associated with a stable cut/segment boundary. If its target segment is overridden, the corresponding auto whip is suppressed.
Rack focus. Identify current and next focus subject from subject selection and authored focus targets. Distance interpolates over exact frame count using a versioned easing curve. Out-of-range distances clamp with a warning. Focus changes across cuts reset interpolation state.
Collision correction. For candidate position next, query world colliders. If current -&gt; next intersects a collider, project along the contact normal and apply configured padding. Re-solve look-at after displacement. A missing collision path skips the layer and logs diagnostics; it must not silently pass through solid geometry.
Occlusion correction. Cast a ray from camera to primary subject. If an occluder is found, apply ordered responses: raise/lower offset, horizontal side offset, configured fallback pose, then framing-weight reduction. If no response preserves subject visibility, report an unresolvable-framing conflict rather than hiding it.
Adaptive framing. Build an axis-aligned bounds from selected active actors. Add margin and smooth the target using a documented first-order filter derived from canonical tick time. EMA coefficients are quantized and versioned. Jitter is controlled by smoothing, not wall-clock delta.
Speed ramp. A cubic or table-based ramp maps normalized segment time to scale. Clamp scale to &gt;= MIN_TIME_SCALE; it must not reverse time. For export, frame numbering remains unchanged; ramping changes camera phase through effective simulation ticks and is serialized explicitly.
Motion vectors. Final current and previous camera matrices feed WP06 velocity. Any reset, cut, seek, collision displacement discontinuity or lens change invalidates history.

Animator issues a rig or IK target command.

Evaluation cache invalidates by scene revision.

Character simulation resolves attacker and defender poses.
Weapon attachment and action state machines produce canonical combat/contact events.

WP14 generates sword trails, impact flashes and secondary contact responses from the same frame inputs.
WP08 converts audio event cues to exact samples.
WP06 consumes final character, weapon, camera and effect packets.
Export repeats the identical chain without editor state.
No consumer may read combat state from a mutable weapon pointer or infer an impact from visual overlap. All action semantics flow through canonical project data and events.
36.3 Auto choreography edit loop
Editor requests dry-run choreography for a scene range.
Planner evaluates a saved revision and immutable action snapshots.
Planner returns shot segments, commands, conflicts and diagnostics.
User may adjust rules and preview without mutation.
Apply submits the command batch through CommandProcessor.
The batch becomes one undo transaction.
Re-evaluation consumes the resulting project revision like any other edit.
Manual keyframes and overrides are stored as project data and constrain future re-plans.
Re-planning is idempotent for unchanged inputs. A changed input invalidates only affected shot segments. Planning never changes character, weapon, particle or audio data implicitly.

Analytic finger IK. Solve each three-link digit in its authored sagittal plane. Clamp target distance to reachable range. Use the authored bend side. Use safe inverse trigonometric functions and canonical deterministic ordering. Degenerate straight/overfolded cases report diagnostics and return the clamped nearest pose.
Thumb opposition. Opposition scalar maps to axial CMC rotation plus palm-arch translation. The remaining IP/MCP solve occurs in the transformed opposition plane.
Object fit. Prop grasp proxies are cylinder, sphere, box or plate. Sample an authored contact band, offset by finger pad thickness, then create per-digit targets. Reject geometry outside hand reach. Contact evaluation. Five finger pads plus palm sites evaluate against prop or body targets. Status is Free, Near, Pressed or Slipping. Contact status is published as diagnostic data; it does not mutate attachment transforms implicitly.
Interpenetration. Use capsule proxies for digit segments, palm and prop collision volumes. Report worst penetration depth, pair IDs and severity. Optional soft correction is bounded to a configured maximum angular delta and may be disabled for strict deterministic review.
Secondary hand. Solve primary hand first. Occupy a region of the handle axis. Calculate the remaining free interval for the second hand. A conflict is a validation error and never produces silent overlap.

L0: full finger solve.
L1: reduced glove-style bones.
L2: mitten silhouette.
L3: hidden detail.
LOD is a pure function of current camera/snapshot, with hysteresis, so seeking produces stable tier selection.

Algorithms
Channel mixing. Face channels are normalized [0,1]. Lane order is fixed:
Baseline &lt; Shot &lt; Intent &lt; Reactive
Each lane contributes:
lane_weight * envelope(t) * preset_channel
Sum in canonical channel order and clamp. Reaction lanes have a bounded amplitude so automatic/layered systems cannot overwrite the authored baseline without control.
Envelopes. Attack, hold and decay durations are rational time converted to exact ticks. The same tick always resolves the same envelope value without accumulated float time.
Blink. Blink timing uses a versioned Philox stream keyed by character ID and blink epoch. Interval, amplitude, close/hold/open phases and kind are deterministic. Context modifiers must be explicit project data, not editor state.
Gaze. A fixation stores target, onset and hold. Saccade duration is quantized from angular distance. Eyes may lead head rotation by authored frames. Large angular targets produce a HeadLookRequest consumed by WP12 neck mechanics.
Convergence. For binocular targets, calculate eye yaw from target position and interpupillary distance. Clamp crossed-eye and extreme pitch values. Orthographic or stylized projection modes use authored simplifications.
Viseme mapping. Use a versioned viseme set, commonly:
Sil, Ah, Ee, Ih, Oh, Oo, W, F, L, R, Mm, N, K
Each viseme maps to mouth, jaw, lip, tongue and cheek channel deltas. Coarticulation uses neighboring cue values and fixed weights. Imported cue lists are saved in project data so evaluation never decodes audio again.
Phonetic import. A rule table converts phonetic tokens to timed visemes. It is deterministic and human-editable. It is not an AI system.
PCM envelope import. Convert waveform amplitude to openness cues offline, normalize with documented floor/peak, store cue list, and never infer emotional expression from amplitude alone.
Cel override key. A close-up face key includes expression bucket, intensity bucket, viseme state, camera side, lid bucket, jaw bucket and optional effects. Lookup uses ordered BTree storage. Missing keys block strict export; nearest-fallback must be explicitly allowed and logged.

L0: full acting and cels.
L1: primary mouth/eye channels.
L2: minimal lid/jaw/mouth.
L3: silhouette only.

Algorithms
Phase allocation. Each mechanic defines ordered legs such as anticipation, windup, strike, follow-through and recovery. Parameters produce a total duration in ticks. Allocate leg widths using rational ratios, floor the integer part, then distribute remaining ticks in canonical leg order. Sum of widths must equal total duration exactly.
Clip sampling. For each leg, map local phase time to the bound animation clip through clamp, loop, ping-pong or authored rate. Sample in fixed layer-slot order. Weight and blend channels using a versioned pose mixer. Missing clips fail before mutation.
Resampling. Convert sub-grid samples to the project’s simulation tick grid. Values use exact tick boundaries and deterministic linear/slerp fallbacks. If source duration is shorter than requested, return InsufficientClipFrames; never extrapolate.
Root motion. Integrate authored velocity/acceleration curves on canonical ticks. Use checked integer/rational time and one fixed floating-point step per tick. Emit sparse keys at direction, speed or phase boundaries, plus contact points. IK/contact generation. Each mechanic declares which body parts may receive overrides. Create targets with authored weight curves and validity ranges. Contact locks must not exceed configured correction magnitude.
Bounded correction. Given a target and current FK position:
delta = target - currentapplied = clamp_magnitude(delta, correction_cap)
Support foot plant, pelvis height, acceleration lean, weapon reach and balance. Over-cap requests clamp and report. They never silently produce a hidden full correction.
Reapply merge. For every key:
If document value differs from baked base and key is animator-touched, preserve document.
If new value differs from base, replace generated value.
If base exists but new does not, remove only untouched generated keys.

Internal logic
Every view is derived from:
(document digest, scene revision, view configuration digest)
Panels never own authoritative data. Drag interaction displays a preview and commits one command on release. Selection state is included in paste transactions and restored by undo.
Dope sheet and X-sheet share the same underlying row/key model, so views cannot disagree. Annotations, ghosts, markers and preferences are saved as project data or explicitly marked session-only.
Algorithms
Derivative measurement. Sample channel values on the exact animation tick grid. First difference:
velocity[i] = value[i+1] - value[i]
Second difference from adjacent velocity values. Normalize by the maximum absolute value only for display; reports retain raw measured spacing. Insufficient samples return a diagnostic rather than extrapolating.
Exposure map. Store per drawable group which source tick is shown at each output tick. Convert ones to twos by selecting authored hold-start poses and recording dropped frames. Converting twos to ones does not invent final poses; generated interpolation keys are explicitly marked and require animator approval.
Onion/ghost. Evaluate existing held exposure schedule at tick ± offset. Ghost poses are captured snapshots stored as project data. Rendering is editor-only.
Silhouette. Project visible part quads and rasterize alpha coverage into a bounded CPU analysis buffer. Metrics:
Coverage area.
Bounding-box fill.
Foreground/background contrast.
Self-occlusion.
Pose readability.
GPU previews may accelerate display, but reported metrics must have a deterministic CPU fallback.
Arc check. For a joint, project world positions to screen space across a frame range. Calculate curvature from consecutive triples and compare radius/turn changes against thresholds. Collinear triples are reported as degenerate samples, not errors.
Action review. Measure anticipation, action and recovery durations from WP20 phases where present. If only authored keys exist, infer phases as suggestions with lower confidence. The report must distinguish authored, generated and inferred data.
Clipboard. Copy produces canonical payload plus hash. Paste assigns new IDs and applies offset/collision policy as one transaction. External clipboard content is parsed by versioned schema and unknown fields are rejected.

Internal logic
A scene qualifies for Level 3 when every required capability is present, editable, deterministic and within its measured resource envelope.
Required production chain:
layered character artwork  -&gt; full-body rig  -&gt; hand/face controls  -&gt; action clip/pose library  -&gt; IK and contact locks  -&gt; secondary motion  -&gt; weapon attachment  -&gt; expression/acting  -&gt; timing review  -&gt; camera/VFX/audio  -&gt; clean export
Automatic motion may be suggested from authored action presets, but the animator retains control over pose, exposure, hand/face state and reaction timing. Level 3 does not require the engine to invent missing performance drawings.
Algorithms
Scene classification. Scan project revision and count:
Unique character rigs.
Active rigs in the shot.
Bones and finger joints.
Face controls.
Visible layers.
Mesh vertices.
Spring-chain nodes.
Particle emitters and maximum live particles.
Lights and post effects.
Unique drawing revisions.
Estimated texture working set.
Audio tracks.
Scene duration and export resolution.
Produce a SceneComplexity record. Classification uses visible/active counts, not total project size, because off-screen state can be culled or frozen.
Memory envelope. Estimate:
render_target_bytes  + active_texture_bytes  + particle_buffer_bytes  + mesh/skinning_bytes  + editor_proxy_bytes  + conservative_headroom
Compare the estimate with observed DXGI budget. The report may pass only if the engine can complete the scene without unsafe eviction and the export remains bounded. Starting budgets are recommendations; measured scene results become authoritative.
Level 3 gate. A scene passes only when:
All required capabilities are enabled.
No critical asset is missing or silently substituted.
Hand, face, contact and action timing remain editable.
Random seek matches sequential simulation.
Memory remains within configured envelope.
Export produces exact frame and sample counts.
Human review records at least one action, one reaction and one expression change.
Repeated export matches the pinned-stack reference.
Hardware tiering. Classify scenes as:
Comfortable: expected to run at interactive preview rates with proxies.
Optimized: requires reduced particle quality or texture streaming.
Export only: editable at low quality but final rendering uses shot segmentation.
Over budget: reject export and report the limiting resources.
